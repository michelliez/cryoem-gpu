## Grilling round 1 (2026-11-25)
- Image size: native 360×360, no crop/downsample.
- Chunked processing on both CPU and GPU (default 500 particles, configurable). For compute timing, preload the host stack; report memmapped streaming read time separately.
- One `xp`-generic implementation (NumPy/CuPy) with a thin backend shim: FFT (`scipy.fft` workers=-1 vs `cupy.fft`), host↔device transfer, synchronize.
- float32/complex64 end to end on both paths; a test asserts dtypes.
- Three timing tiers per measurement: T_compute (device-resident, synchronized), T_e2e (host in/out incl. H2D/D2H), T_io (disk/memmap read, shared). Headline uses T_e2e.
- Normalization stays in the full pipeline and as a per-op table row; no chart, no headline.
- Download script: size check against `1024 + n·518400`, skip verified files, modest parallelism. Target dir (`/kaggle/working` vs `/kaggle/temp`) checked at first run.
- Tests: CPU-only pytest locally on synthetic stacks always. The real 97-particle stack is an optional test that downloads on first use and skips if offline; never committed. GPU tests skip when CuPy is absent. On Kaggle, CPU-vs-GPU agreement tests gate every benchmark run, with float32 tolerances (relative error ~1e-5–1e-4) defined in one config, not per test.
- 3D demo: FFT-based 3D low-pass on EMD-2660 (not `scipy.ndimage.gaussian_filter`, which is single-threaded), with transfer-vs-compute breakdown.
- README CPU caveat: report measured core count; say qualitatively that a multicore workstation would narrow the gap; no extrapolated numbers.

## Grilling round 2 (2026-11-25)
- CTF: RELION formula. CTF = +(√(1−A²)·sin χ + A·cos χ) (corrected 2026-11-25: RELION's `-sin(K1·Δf'·s² + K2·s⁴ − K3)` with Δf' = −Δf expands to the + form; the − form is cryoDRGN's convention), χ = π·λ·Δf(θ)·s² − (π/2)·Cs·λ³·s⁴; astigmatic Δf from U/V/angle; relativistic λ at 300 kV; Cs mm→Å; no B-factor, no phase shift. Phase flip multiplies by sign(CTF) with sign(0)=+1. Sign array computed per chunk on the active backend and counted in timings.
- CTF validation independent of CPU/GPU agreement: closed-form unit tests (non-astigmatic χ zero crossings, λ(300 kV) ≈ 0.01969 Å, U↔V swap with angle+90° invariance) plus a Thon-ring figure (mean power spectrum of one micrograph's particles with predicted zeros overlaid). No external reference package.
- Full pipeline is fused: normalize → rfft2 → ×(lowpass·sign(CTF)) → irfft2 (one FFT pair). Per-op benchmarks time normalize, rfft2, irfft2, lowpass multiply, CTF compute+flip separately.
- Low-pass: raised-cosine edge, 10 Å cutoff, ~5 Fourier-pixel edge; both configurable.
- Normalization: RELION-style background normalization (mean/std of pixels outside radius 150 px, configurable).
- CPU baseline: serial (scipy.fft workers=-1) and threaded (chunk thread pool sized to measured core count, scipy.fft workers=1 inside to avoid oversubscription). Report both; headline speedups use whichever CPU config is faster. Document that NumPy elementwise ops are single-threaded. If threading is more than small effort, fall back to serial-only + documentation for the MVP.
- Particle counts 100 / 1,000 / 5,000 / 10,000 (prefixes). One warm-up per config. CPU trials 10/10/5/3, GPU 20. Rows record median, min, max, n_trials.
- Timing: perf_counter on both backends, explicit device synchronize before/after on GPU. One-off CUDA-event cross-check of T_compute.
- T_e2e uses pinned host memory. Stream overlap of transfer/compute is a stretch goal.
- Results: append each measurement immediately to results/benchmarks.csv keyed on (experiment, op, backend, n_particles, chunk_size, tier), skip existing keys, every row carries a hardware/software fingerprint. Canonical Kaggle run's CSV and figures are committed; README numbers come only from that CSV; figures generated by script.
- GPU chunk-size sweep (100/250/500/1000/2000, full pipeline at 10k) is a stretch goal.
- Repo layout: src/cryoem_gpu/{io,star,ctf,filters,pipeline,backend,bench}, scripts/{download_subset,run_benchmarks,make_figures}.py, notebooks/cryoem_gpu_kaggle.ipynb, tests/, results/, docs/, pyproject.toml (pip install -e .).
  - data/ is gitignored; results/ (CSV + figures) is committed.
  - The Kaggle notebook installs the package via `pip install git+https://github.com/michelliez/cryoem-gpu` so it always runs repo code.
  - CuPy is not a core dependency; add an optional `[gpu]` extra and/or README note naming cupy-cuda13x.

## Ticket 06: filters (2026-11-25)
- `normalize` accumulates the background mean/std in float64 and casts back, so every stage array stays float32. With float32 accumulation the mean drifted ~1.2e-4 on a background offset of 50 (measured), which failed the mean ≈ 0 check. The reduction is memory-bound, so the T4's slow FP64 should cost little. If the M4.5 per-op timing says otherwise, switch to a float32 two-pass mean.
- `lowpass` computes the Fourier-pixel radius from integer indices (`fftfreq(n, d=1/n)`). This equals `s·box·pixel_size` for a cubic box and avoids float32 rounding at the band edges. Non-cubic shapes raise `ValueError`.

## Ticket 07: CTF (2026-11-25)
- `ctf` takes `CtfParams` in STAR units (defocus Å, angle degrees, voltage kV, Cs mm) and converts inside. The spec formula's volts, radians and Å for Cs stay internal, so callers pass STAR columns unchanged.
- Defocus and χ are computed inline in `ctf()` rather than as separate public functions (spec §4 lists them). Nothing else needs them yet.
- `ctf_closed_form` tolerance is 1e-4 absolute, not 1e-5: the U↔V swap identity differs by ~6e-5 in float32 (measured) because χ reaches ~500 rad at the 360² grid corner.
- `ky` orientation is still as in §3.1 (unflipped). The Thon-ring figure (ticket 15) decides it; no test here ties φ to the image's y direction.
